Week 1 21 Feb – 28 Feb
🚀 Launch — Agree Everything Before Anyone Writes a Single Line of Code
📅 Meeting 1 — Foundation Session 21–22 Feb
  • Choose your SDG from the 17 UN goals — pick one everyone is genuinely interested in, not just the easiest
  • Agree on 2–3 main colours for the website and write them down so everyone uses the same ones
  • Agree on the font — pick one from Google Fonts that suits your SDG theme
  • Decide on a 5-letter team name for your folder — tell your tutor this within the first 2 weeks
  • Confirm all file names exactly match the spec (home.html, gallery.html, splash.html, etc.)
  • Sign the Group Contract — required for submission, get it done now
  • Create a shared Google Drive folder and make sure everyone has access
💡Write all your agreed decisions in a shared doc — colours, font name, SDG choice, team name. Refer back to it throughout the project so you stay consistent.
Week 2 1 Mar – 7 Mar
🔗 Mid-Project Check — Make Sure Everyone's Pages Connect
📅 Meeting 2 — Template Review & Cross-Link Check 1–2 Mar
  • Every student confirms they have successfully copied the shared template and it displays correctly in a browser
  • Open all navigation links from each person's page and verify they point to the correct file names — fix any broken paths now
  • Confirm the global CSS is loading correctly on every page — check fonts, colours, and nav styling are consistent
  • Agree on the exact folder structure on the university server — confirm everyone is using the same relative file paths
  • Raise any design issues — if someone's page looks visually inconsistent with the rest, agree on a fix now
  • Each person gives a quick update on their Week 2 progress — flag anything that might run late
💡This is the most common failure point in group web projects — someone uses a different folder structure and all the links break. Agree on paths in this meeting and write them down.
Week 3 8 Mar – 14 Mar
⚡ JavaScript Week — Check Everyone's Interactive Features Work
📅 Meeting 3 — JavaScript Progress Review 8–9 Mar
  • Each student demonstrates their page's interactive JavaScript feature — gallery expand, AIS scoring, feedback form, or profile prompts
  • Check that the active page nav state is correctly set on every page — the current page's link must look different
  • Test navigation between pages — click every nav link from every page and confirm nothing is broken
  • Check every footer has the correct Page Editor and Validation links for that page's assigned student
  • Flag any pages that are behind schedule — agree on a plan to catch up before Week 4
📅 Meeting 4 — Pre-Submission Final Review 15–16 Mar
  • Every student shows their completed pages — all main pages, content page, and any that are ready
  • Check every single image across every page has alt text — this is the most common validation error
  • Confirm all pages still use the shared template — nobody has accidentally changed the header or footer structure
  • Agree on who still has outstanding work and set a hard personal deadline to finish before server upload
  • Remind everyone to start their Page Editor and Validation pages this week — not at the last minute

Week 21 Mar – 7 Mar
🗺️ Build the Sitemap and Start the Profile Page
🧭
Challenge 2 — Complete sitemap.html
02
  • Copy the shared template and rename it sitemap.html
  • Draw the entire website structure as SVG — not a screenshot, not a regular image, actual SVG code
  • Represent every required page as a shape (rectangle or rounded box) with the page name as text inside
  • Connect shapes with lines to show which pages are linked to which
  • Make every shape a clickable link that goes to the corresponding page
  • Add hover effects on shapes — fill colour, border, or opacity change on mouse-over — using CSS
  • Add a visible focus state to every clickable node — this is an explicit accessibility requirement in the brief. When a user tabs to a node using the keyboard, it must visually change (e.g. an outline, a stroke highlight, or a colour shift). You can reuse the hover styling or create a dedicated focus style, but it must be present and visible
  • Add a title element inside each SVG link for accessibility — screen readers use this
  • Set the SVG viewBox attribute and make its width 100% so it scales on different screen sizes
  • Make sure the sitemap colours match the team's agreed colour palette
  • Make the Sitemap nav link show as active on this page
